# 项目团队（dsh-session-team）

把会话按**项目**组织成一支支团队：每支团队有自己的 Lead、成员、模型、派活台账与汇报队列。
面板分两层——先是「项目团队」列表（像侧栏的工作区列表），点进某支团队才看成员、派活、汇报、恢复。

## 它做什么

- **多团队**：`teams.json` 里存多支团队（名字、工作目录、Lead、成员）。面板顶部是团队列表，
  显示每队的人数、Lead、运行数、未完成任务、待读汇报；点开进详情。
- **三种建队/加人方式**：
  1. 团队列表页「新建项目团队」：填工作目录（绝对路径，输入框带工作区下拉提示）、团队名，
     逐行填成员名 / 角色 / 优先级 / 模型 / 思考强度 / Agent 模式，勾一个 Lead → 插件新建会话、设模型、
     把标题改成 `团队名 · 成员名`，写入名单并切到该团队；
  2. 团队详情页成员卡片底部左下「＋ 添加角色」：等价于新建 session，可一次加多行
     （名称/角色/优先级/模型/**思考强度**/**Agent 模式**，可选设为 Lead），建好直接加入**当前**团队；
     和「新建项目团队」用的是同一套行编辑与「添加一行」按钮；
  3. 团队详情页「从已有会话加入」：把侧栏里已有的会话登记为成员，上下文/权限/模型保持原样。
- **一个 Lead**：只有该团队的 Lead 能看到 `team_roster`、`team_dispatch`、`team_collect`、
  `team_models`、`team_recover`；普通成员只看到 `team_report`。工具按**调用者所在的团队**工作，
  不同团队互相隔离。
- **项目分组**：创建会话时传入该团队目录对应的 `workspaceId`，并把会话 `attachSession` 到该项目；
  从已有会话加入时只补挂不属于其他项目的会话；`attach-workspace` 动作可整体补齐；
- **长列表优化**：任务/汇报卡片带「未完成 / 全部」「未读 / 全部」标签页与计数，默认只看未完成与未读；
  列表限高滚动、分页「显示更多」、汇报正文两行折叠可展开、整张卡片可折叠并记住状态；历史最多加载最近 50 条；
- **成员变动通知**：新建团队、新增角色、已有会话加入、移除成员、修改角色/优先级、切换 Lead 后，
  插件把「成员名单 + 角色 + 优先级」作为排队消息发给团队 Lead（Lead 忙时留在 `ledger.json`，
  空闲后自动送达；面板显示「待通知 N」，也可用「立即投递」强制送达）；
- **优先级与拖动排序**：成员带一个「优先级」编号（数字小越先处理），可直接**拖动成员行**排序或点 ↑/↓ 微调，排序后优先级自动重排；汇报按优先级升序、同优先级按先后排队；Lead 在跑的时候只排队，
  `idle` 时才合并成一条摘要投递；Lead 也可以自己 `team_collect` 主动拉。
- **派活台账与中断恢复**：每次派活记进 `ledger.json`；DSH 被强退/重启后，面板「任务与恢复」
  能看到谁的任务停在半道（冷会话立即判定；活着的会话要空闲且无排队输入、超过 5 分钟才判定），
  一键发「先汇报实际进度、再从断点继续」；`done` 汇报会自动关单。
- **每个角色可选 Agent 模式**：新建团队或添加角色时逐行选「标准模式 / PTC 模式 / 极简模式 /
  创造模式」等（默认标准模式），按所选 preset 建会话；已有成员也能在成员行里改模型。
- **每个角色单独换模型**：成员行「角色/模型」里选 provider / 模型 / 推理强度；只写该会话的
  `model/selection`、不改全局默认、下一回合生效；冷会话会被短暂激活（不会开跑）。

## 数据文件

- `$DSH_HOME/session-team/teams.json`：团队清单 + 当前选中的团队。
- `$DSH_HOME/session-team/ledger.json`：派活台账 + 未送达汇报。
- 旧版插件写的单团队 `roster.json` / Config `members` 会在首次启动时迁移成一支 `team-legacy`；
  旧台账会归到这支团队。

## 用法

1. 侧栏点「项目团队」图标 → 团队列表。
2. 「新建项目团队」建一支新的；或点开已有团队进详情。
3. 详情里：看成员状态/模型、改角色与模型、设 Lead、从已有会话加入、派活、看任务与恢复、读汇报。
4. 右上按钮：刷新、立即投递、恢复未完成、生成 Lead 说明、从已有会话加入、删除团队；
5. 面板记住上次打开的团队与视图，下次打开插件直接回到该团队详情。

## 工具（按调用者所在团队解析）

| 工具 | 可见于 | 作用 |
|---|---|---|
| `team_roster` | 团队的 Lead | 列出本团队成员、在线状态、排队输入、待读汇报数 |
| `team_dispatch` | 团队的 Lead | 按成员名 / session id / `all` 派活 |
| `team_collect` | 团队的 Lead | 按阶段顺序读取并消费汇报 |
| `team_models` | 团队的 Lead | 列出可用模型；带 member+provider+model 时给成员换模型 |
| `team_recover` | 团队的 Lead | 找出被中断/停下未汇报的任务并发送恢复提示 |
| `team_report` | 普通成员 | 把进度/结果/阻塞写进本团队汇报队列 |

## 限制与边界

- 汇报队列与台账持久化在插件数据目录；DSH 重启后未送达的汇报会补投。
- 成员必须是已存在的普通会话；子代理会话不能作为成员。
- 换模型会短暂激活该成员的会话（`resolveAgent`，不会开跑），并在它的日志里写一条 `model/selection`。
- 正在跑的回合不会被换模型打断：新模型从该会话的下一个回合生效。
- 恢复只处理台账里还开着的任务；成员自发的工作不追踪。在旧版台账上线前派出的任务，
  需要重新派活或手动登记。
- 不负责工作目录隔离：同一工作区并行时，请在任务里自己划分文件范围。
- 删除团队只移除名单，不删除会话。
